**Profile model (contract for T34).** `packages/protocol/src/profile.ts` + `schema/policy-profile.schema.json`:

```jsonc
{
  "id": "herdr-shipped",                 // or "cockpit", "lstack-herdr", a user's own
  "folders": ["files", "changes", …],     // exact mod folder names this profile governs
  "requires": { "herdr": ">=0.1.13" },   // optional; mismatch → still applied, logged + banner
  "reads":  { "appHome": ["data/{folder}/**", "icons/**", "my-icons/**", "layouts/*.svg"], "spaces": true, "extra": ["~/.cache/lstack-herdr"] },
  "writes": { "extra": [] },             // only runner profiles may write; listed for the log
  "exec":   { "rows": ["E4", "E5", "E6", "E7", "E11", "E14"], "git": { "gitDirUnderRoots": false } },
  "scripts": { "mods/lstack-herdr/components/lh-scan.mjs": "lh-scan" },   // E1/E2 keys → runner profile ids (code)
  "shLiterals": { "<sha256>": "listing" },                                 // E14/E15 pins, per Herdr version
  "net":    { "hubPortFrom": "cockpit.json" },                              // or absent
  "overlay": "device" | "host-only"                                         // host-only ⇒ mod.open on a device toasts
}
```
Rules (invariants): rows stay code (argument-level checks + tests); a profile can only **enable** a row, never widen a row's argument grammar beyond what the row's own flags allow; folders not matched by any profile get `default` = `{reads: own folder + data/<folder> + spaces, exec: none, hc: none, net: none, overlay: "device"}`; a folder matched by several profiles takes the **most specific** (longest `folders` list wins is wrong — use explicit `priority`, built-ins 0, user 10); user profiles live in `<state>/profiles/*.json` (0600, validated with the schema, invalid file → logged and ignored); the applied profile id is sent in `hello.hosts[].profile` and logged in every policy record (`PolicyLogRecord.profile`).

## 4. Network / onboarding

Today **[V]** `auth/gate.ts`: tailnet (`Tailscale-User-Login` = owner, `Host` = MagicDNS, peer from tailscaled, `Origin` + `X-Herdr-Relay` for writes) or loopback (token / same-origin). Pairing (6-digit, 2 min, 5 wrong → void), httpOnly `__Secure-…` cookie, one-time WS ticket are **independent of Tailscale** and stay the second factor.

| Option | How | Security trade-off | Cost |
|---|---|---|---|
| A. Tailscale-only (today) | `tailscale serve --set-path` | identity + WireGuard + valid TLS cert for free; strongest | 0 |
| B. **Reverse-proxy mode** | Bridge stays on loopback; user runs Caddy/nginx/Cloudflare Tunnel with HTTPS; `HERDR_RELAY_ACCESS=proxy HERDR_RELAY_PUBLIC_HOST=relay.example.com`; gate requires loopback peer + `X-Forwarded-Proto: https` + exact `Host`; optional `HERDR_RELAY_IDENTITY_HEADER`/`_VALUE` (e.g. `Cf-Access-Authenticated-User-Email`) generalizes the Tailscale login check | Without an identity header the network factor is gone: pairing code + cookie + ticket + custom header are the whole auth → documented as "run it inside your VPN/LAN or add Cloudflare Access/Authelia"; pairing lockout + per-IP rate limit on `/api/pair` added | ~1 task; small gate change; docs with a Caddy snippet |
| C. Built-in TLS on LAN | Bridge mints a CA + leaf (needs an ASN.1 encoder or `openssl` spawn), serves `Deno.serve({cert,key})` **[I]**; iOS/Android must install and trust the CA profile for PWA/Web Push | high onboarding friction, more code, `.local` names can't get public certs | 2–3 tasks |
| D. Refuse non-Tailscale | status quo | excludes users | 0 |

**Recommendation:** A default + **B opt-in in v1**; C deferred (track as v1.x). `herdr-relay serve` exists only in mode A; `herdr-relay doctor` explains the active mode. Pairing UI copy becomes mode-aware (G16).
